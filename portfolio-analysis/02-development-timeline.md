## 타임라인에서 드러나는 개발 방식

1. 큰 기능을 contract/schema → backend → AI/FE → QA phase로 나눴다.
2. 자동 review 지적은 후속 commit으로 반영했지만 사람 review 대화는 남아 있지 않다.
3. 초기 seed·stub·CSV source처럼 임시 접근을 먼저 만들고, 운영 제약이 드러난 뒤 pipeline·live API·OpenAPI로 교체했다.
4. 구현 속도는 빨랐지만 final merge 직전 직접 `develop` commit과 `#0` commit이 늘어 issue/PR traceability가 약해졌다.
5. 문서 업데이트가 대부분 feature PR에 함께 들어갔지만, 일부 최종 문서와 현재 구현 사이에는 contract drift가 남았다.
