# 요구사항정의서

## 1. 프로젝트 개요

살만해는 AI 에이전트 기반 부동산 탐색 서비스이다. 사용자는 지도에서 매물을 탐색하고, 로그인 후 AI 챗봇에 자연어로 질문해 매물 추천, 임대차 법률 상담, 시세 분석, 주변 안전시설 분석을 받을 수 있다.

서비스의 핵심 목적은 단순 매물 중개가 아니라 계약 전 판단에 필요한 가격, 위치, 안전, 법률 정보를 한 흐름에서 확인하도록 돕는 것이다.

## 2. 문제 정의

| 문제 | 설명 |
| --- | --- |
| 계약 안전 정보 해석 어려움 | 청년 1인 가구와 부동산 계약 경험이 적은 사용자는 전세사기, 깡통전세, 보증금 회수, 임대차 법률 정보를 직접 판단하기 어렵다. |
| 정보 분산 | 매물 정보, 실거래가, 주변 안전시설, 법률 조항이 서로 다른 서비스와 공공 데이터에 분산되어 있다. |
| 기존 서비스의 한계 | 기존 부동산 서비스는 매물 탐색과 중개 중심이며, “이 집이 살 만한가”에 대한 통합 판단 보조가 부족하다. |
| 공공 데이터 활용의 어려움 | 실거래가와 생활안전 데이터는 신뢰도가 높지만 사용자가 직접 비교·해석하기 어렵다. |

## 3. 사용자 및 이해관계자

| 구분 | 설명 | 주요 니즈 |
| --- | --- | --- |
| 비회원 사용자 | 로그인 없이 서비스를 탐색하는 사용자 | 지도 기반 매물 위치, 가격, 시세, 안전시설 확인 |
| 회원 사용자 | AI 상담 기능을 사용하는 사용자 | 자연어 매물 추천, 법률 RAG 상담, 선택 매물 시세·안전 분석 |
| 서비스 운영자 | 데이터 수집, 배치, 배포, 품질 관리를 담당하는 운영 주체 | 공공 데이터 적재, API 안정성, 환경변수와 배포 관리 |
| AI 에이전트 | FastAPI + LangGraph 기반 내부 서비스 | 질문 의도 분류, worker 실행, 근거 기반 답변 생성 |
| 공공 API | 실거래가와 안전시설 원천 데이터 제공자 | 정규화 후 DB 저장에 활용 |

## 5. 기능 요구사항

### 5.1 지도 기반 매물 탐색

| ID | 요구사항 |
| --- | --- |
| FR-MAP-01 | 사용자는 지도 화면에서 현재 viewport bounds 안의 매물과 지역 정보를 조회할 수 있어야 한다. |
| FR-MAP-02 | 시스템은 지도 zoom 값에 따라 시/도 평균, 시/군/구 평균, 읍/면/동 평균, 클러스터, 개별 매물 표시 모드를 구분해야 한다. |
| FR-MAP-03 | 사용자는 거래유형, 매물유형, 보증금/매매가 범위, 키워드 검색 조건을 적용할 수 있어야 한다. |
| FR-MAP-04 | 사용자가 매물을 선택하면 상세 패널에 가격, 면적, 층수, 주소, 설명을 표시해야 한다. |
| FR-MAP-05 | 매물 상세에서는 주변 실거래가와 안전 요약 정보를 함께 확인할 수 있어야 한다. |

### 5.2 인증

| ID | 요구사항 |
| --- | --- |
| FR-AUTH-01 | 사용자는 이메일 인증 코드를 요청할 수 있어야 한다. |
| FR-AUTH-02 | 사용자는 이메일로 받은 인증 코드를 검증할 수 있어야 한다. |
| FR-AUTH-03 | 이메일 인증 완료 후 회원가입할 수 있어야 한다. |
| FR-AUTH-04 | 로그인 성공 시 access token과 refresh token을 발급해야 한다. |
| FR-AUTH-05 | refresh token 갱신 시 access token과 refresh token을 모두 새로 발급해야 한다. |
| FR-AUTH-06 | 로그아웃 시 Redis에 저장된 refresh token을 삭제해야 한다. |

### 5.3 AI 에이전트

| ID | 요구사항 |
| --- | --- |
| FR-AI-01 | 프론트엔드는 FastAPI를 직접 호출하지 않고 Spring Boot `/api/v1/chat`만 호출해야 한다. |
| FR-AI-02 | Spring Boot는 JWT 검증 후 내부 HTTP로 backend-ai에 메시지를 전달해야 한다. |
| FR-AI-03 | backend-ai는 LangGraph supervisor 패턴으로 질문 의도에 맞는 worker를 선택해야 한다. |
| FR-AI-04 | AI worker는 매물 검색, 법률 상담, 시세 분석, 안전 분석, 일반 대화를 처리할 수 있어야 한다. |
| FR-AI-05 | AI 응답은 자연어 답변과 함께 매물 카드, 법률 카드, 분석 카드 중 필요한 데이터를 반환해야 한다. |

### 5.4 법률 RAG 상담

| ID | 요구사항 |
| --- | --- |
| FR-LEGAL-01 | 시스템은 임대차 관련 법령 문서를 chunk 단위로 저장해야 한다. |
| FR-LEGAL-02 | backend-ai는 사용자 법률 질문을 embedding하고 pgvector 유사도 검색을 수행해야 한다. |
| FR-LEGAL-03 | 법률 상담 응답에는 법령명, 조항, 제목, 내용 요약, 유사도 점수 등 근거 카드가 포함될 수 있어야 한다. |
| FR-LEGAL-04 | 법률 답변은 일반 조언으로 제공되며, 전문 법률 자문을 대체하지 않는 방향으로 안내해야 한다. |

### 5.5 시세·안전 분석

| ID | 요구사항 |
| --- | --- |
| FR-ANALYSIS-01 | 매물 주변 실거래가는 `building_key`를 우선 사용하고, 부족한 경우 법정동/유형/면적 조건으로 확장 조회해야 한다. |
| FR-ANALYSIS-02 | 지역/건물 시세 통계는 `region_price_stat`, `building_price_stat`에 저장된 데이터를 조회해야 한다. |
| FR-ANALYSIS-03 | 안전시설은 요청 시점에 공공 API를 직접 호출하지 않고 DB에 저장된 좌표 데이터를 조회해야 한다. |
| FR-ANALYSIS-04 | 매물별 안전 점수는 배치에서 사전 계산해 `property_score_stat`에 저장해야 한다. |
| FR-ANALYSIS-05 | AI 안전 분석은 Spring Boot 안전 요약 API를 호출해 안전 점수와 시설 수를 답변에 반영해야 한다. |

### 5.6 공공 데이터 수집 및 저장

| ID | 요구사항 |
| --- | --- |
| FR-DATA-01 | 국토교통부 실거래가 데이터는 정규화 후 `transaction_history`에 저장해야 한다. |

| FR-DATA-04 | 런타임 조회 API는 저장된 DB 데이터를 우선 사용해야 한다. |

## 6. 비기능 요구사항

| 구분 | 요구사항 |
| --- | --- |
| 보안 | API 키, DB 비밀번호, JWT secret, 내부 API key는 환경변수로 관리한다. |
| 인증/인가 | 인증이 필요한 API는 Spring Security JWT 필터를 통과해야 한다. |
| 서비스 분리 | LLM 호출과 LangGraph agent는 backend-ai에만 위치한다. |
| 통신 경계 | Frontend는 Spring Boot만 호출하고, Spring Boot와 backend-ai는 내부 HTTP로 통신한다. |
| 데이터 일관성 | 공공 API 데이터는 정규화 후 DB에 저장하고, 클라이언트 요청 시에는 DB를 조회한다. |
| 응답 형식 | Spring Boot API는 `data`, `message`를 포함하는 camelCase JSON 응답 형식을 따른다. |
| 성능 | 지도 viewport 조회는 zoom별 표시 모드와 인덱스를 활용해 화면 렌더링 부담을 줄인다. |
| 유지보수성 | 비즈니스 로직은 Service 계층에 두고 Controller/Router는 입력 검증과 위임을 담당한다. |
| 테스트 | Backend, AI Backend, Frontend의 주요 API와 유틸리티에 대해 자동화 테스트를 작성한다. |

## 7. 시스템 제약사항

| 제약 | 내용 |
| --- | --- |
| FE-BE 통신 | Frontend는 Spring Boot REST API만 직접 호출한다. |
| BE-AI 통신 | Spring Boot와 FastAPI 사이 통신은 내부 HTTP만 사용한다. |
| AI 경계 | Spring Boot는 직접 LLM을 호출하지 않는다. |
| RAG 검색 | pgvector 유사도 검색은 backend-ai에서만 수행한다. |
| 런타임 데이터 조회 | 지도, 매물, 시세, 안전 분석 API는 저장된 DB 데이터를 기반으로 동작한다. |
| MVP 제외 | 커뮤니티, 실매물 중개, HUG 정밀 판정, 등기부등본 AI 분석은 MVP 범위에 포함하지 않는다. |

## 8. 인수 기준

| 기능 | 인수 기준 |
| --- | --- |
| 지도 탐색 | bounds, zoom, 필터 조건에 따라 지역 평균, 클러스터, 개별 매물 데이터가 반환되고 화면에 표시된다. |
| 매물 상세 | 매물 ID로 상세 정보를 조회할 수 있고, 존재하지 않는 매물은 오류 응답을 반환한다. |
| 주변 실거래가 | 선택 매물 기준 최근 실거래가 목록을 조회할 수 있다. |
| 안전시설 조회 | bounds와 시설 유형 조건에 따라 안전시설 목록을 조회할 수 있다. |
| 인증 | 이메일 인증, 회원가입, 로그인, refresh, logout 플로우가 정상 동작한다. |
| AI 챗봇 | 로그인 사용자가 질문을 전송하면 자연어 답변과 필요한 카드 데이터가 반환된다. |
| 법률 RAG | 임대차 법률 질문에 대해 관련 법령 카드와 설명이 반환된다. |
| 시세 분석 | 법정동, 매물유형, 거래유형 기준으로 지역/건물 시세 통계가 반환된다. |
| 안전 분석 | 선택 매물 기준 저장된 안전 점수와 시설 수가 분석 카드에 포함된다. |
