# 요구사항정의서

## 1. 프로젝트 개요

살만해는 AI 에이전트 기반 부동산 탐색 서비스이다. 사용자는 지도에서 매물을 탐색하고, 자연어로 조건을 입력해 매물 추천, 시세 분석, 안전시설 분석, 임대차 법률 상담을 받을 수 있다. 서비스의 핵심 가치는 단순 중개가 아니라 계약 전 안전성 검증이다.

## 2. 문제 정의

| 문제 | 설명 |
| --- | --- |
| 계약 안전 정보 해석 어려움 | 청년 1인 가구가 전세사기, 깡통전세, 선순위 권리, HUG 보증 조건을 직접 판단하기 어렵다. |
| 정보 분산 | 실거래가, 안전시설, 법률 조항, 매물 정보가 서로 다른 서비스와 공공 API에 분산되어 있다. |
| 기존 서비스의 한계 | 기존 부동산 서비스는 매물 탐색과 중개 중심이며 "계약해도 안전한가"에 대한 통합 답변이 약하다. |

## 3. 사용자 및 이해관계자

| 구분 | 설명 | 주요 니즈 |
| --- | --- | --- |
| 비회원 사용자 | 지도 기반 탐색을 먼저 해보는 사용자 | 매물 위치, 가격, 주변 안전정보 확인 |
| 회원 사용자 | AI 상담과 저장 기능을 쓰는 사용자 | 자연어 추천, 법률 RAG, 시세/안전 분석 |
| 서비스 운영자 | 데이터 수집/배치/품질 관리 담당 | 공공 데이터 적재, API 안정성, 배포 관리 |
| AI 에이전트 | 내부 FastAPI/LangGraph 서비스 | 사용자 질문 의도 분류, 워커 실행, 답변 생성 |

## 4. 서비스 범위

### MVP 범위

| ID | 기능 | 요구사항 | 인증 |
| --- | --- | --- | --- |
| F-1 | 지도 기반 매물 탐색 | 네이버지도 SDK 기반 지도 표시, bounds/zoom 기준 매물·지역 평균·클러스터 조회, 거래유형/매물유형/가격/키워드 필터 | 일부 공개 |
| F-2 | AI 매물 추천 | 사용자의 자연어 조건을 해석해 조건에 맞는 매물 카드와 응답 반환 | 필요 |

| F-4 | 시세·안전 분석 | 실거래가/지역 통계와 저장된 안전 점수 기반 분석 카드 반환 | 일부 공개 |
| F-6 | 인증 | 이메일 인증, 회원가입, 로그인, JWT 발급, refresh token rotation, 로그아웃 | 공개/필요 혼합 |

## 5. 기능 요구사항

### 5.1 지도 기반 매물 탐색

| 항목 | 요구사항 |
| --- | --- |
| FR-MAP-01 | 사용자는 지도 화면에서 현재 viewport 안의 매물을 조회할 수 있어야 한다. |
| FR-MAP-02 | 지도 zoom에 따라 시/도 평균, 시/군/구 평균, 읍/면/동 평균, 클러스터, 개별 매물을 다르게 표시해야 한다. |
| FR-MAP-03 | 거래유형, 매물유형, 보증금/매매가 범위, 키워드 조건을 적용할 수 있어야 한다. |
| FR-MAP-04 | 매물 선택 시 상세 패널에 가격, 면적, 층수, 주소, 설명을 표시해야 한다. |

### 5.2 인증

| 항목 | 요구사항 |
| --- | --- |
| FR-AUTH-01 | 사용자는 이메일 인증 코드를 요청하고 검증할 수 있어야 한다. |
| FR-AUTH-02 | 이메일 인증 완료 후 회원가입할 수 있어야 한다. |
| FR-AUTH-03 | 로그인 성공 시 access token과 refresh token을 발급해야 한다. |
| FR-AUTH-04 | refresh token 갱신 시 access/refresh token을 모두 새로 발급해야 한다. |
| FR-AUTH-05 | 로그아웃 시 Redis에 저장된 refresh token을 삭제해야 한다. |

### 5.3 AI 에이전트

| 항목 | 요구사항 |
| --- | --- |
| FR-AI-01 | 프론트엔드는 FastAPI를 직접 호출하지 않고 Spring Boot `/api/v1/chat`만 호출해야 한다. |
| FR-AI-02 | Spring Boot는 JWT 검증 후 내부 HTTP로 backend-ai에 요청을 전달해야 한다. |
| FR-AI-03 | backend-ai는 LangGraph supervisor 패턴으로 워커를 선택해야 한다. |
| FR-AI-04 | 사용 가능한 워커는 매물 검색, 법률 상담, 시세 분석, 안전 분석, 일반 대화이다. |
| FR-AI-05 | 응답은 자연어 답변과 함께 매물 카드, 법률 카드, 분석 카드 중 필요한 데이터를 반환해야 한다. |

### 5.4 시세·안전 분석

| 항목 | 요구사항 |
| --- | --- |
| FR-ANALYSIS-01 | 매물 주변 실거래가는 `building_key` 우선, 부족 시 법정동/유형/면적 조건으로 확장 조회해야 한다. |
| FR-ANALYSIS-02 | 안전시설은 공공 API를 런타임에 직접 호출하지 않고 DB에 저장된 좌표만 조회해야 한다. |
| FR-ANALYSIS-03 | 매물별 안전 점수는 배치에서 사전 계산해 `property_score_stat`에 저장해야 한다. |
| FR-ANALYSIS-04 | AI 안전 분석은 Spring Boot 안전 요약 API를 호출해 점수와 시설 수를 답변에 반영해야 한다. |

## 6. 비기능 요구사항

| 구분 | 요구사항 |
| --- | --- |
| 보안 | API 키와 시크릿은 환경변수로 관리하고 코드에 하드코딩하지 않는다. |
| 인증/인가 | 인증 필요 API는 Spring Security JWT 필터를 반드시 통과해야 한다. |
| 아키텍처 | 모든 비즈니스 로직은 Service 계층에 둔다. Controller/Router는 검증과 위임만 담당한다. |
| 서비스 분리 | LLM/LangGraph는 backend-ai에만 존재하며 Spring Boot는 직접 LLM을 호출하지 않는다. |
| 데이터 | 공공 API 데이터는 배치로 수집 후 DB에 저장하고 클라이언트 요청 시 DB만 조회한다. |
| 응답 형식 | Spring Boot API 응답은 `data`, `message`를 포함하는 camelCase JSON을 따른다. |
| 테스트 | 신규 기능은 테스트를 먼저 작성하고 구현하는 TDD 원칙을 따른다. |

## 7. 주요 제약사항

- Frontend는 Spring Boot REST API만 직접 호출한다.
- Spring Boot와 FastAPI 사이 통신은 내부 HTTP만 사용한다.
- pgvector 유사도 검색은 FastAPI에서만 수행한다.
- 데이터 모델 변경 시 `docs/07_DOMAIN_MODEL.md` 업데이트가 필요하다.
- API 응답 형식 변경 시 `docs/08_API_SPEC.md` 업데이트가 필요하다.

## 8. 인수 기준

| 기능 | 인수 기준 |
| --- | --- |
| 지도 탐색 | bounds/zoom/필터 조건에 따라 지역 평균, 클러스터, 매물 마커가 정상 표시된다. |
| 매물 상세 | 매물 ID로 상세 정보를 조회하고 존재하지 않는 매물은 404 오류를 반환한다. |
| 인증 | 이메일 인증, 회원가입, 로그인, refresh, logout 플로우가 정상 동작한다. |
| AI 챗봇 | 로그인 사용자가 질문하면 `workersCalled` 기반 결과와 답변이 반환된다. |
| 법률 RAG | 법률 질문에 대해 조항 카드와 설명이 반환된다. |
| 안전 분석 | 선택 매물 기준 저장된 안전 점수와 시설 수가 분석 카드에 포함된다. |

## 9. SSAFY HOME 필수 기능 대응

참고 명세의 필수 기능은 그대로 복제하지 않아도 되는 것으로 확인했으나, 제출 문서에서는 어떤 방식으로 대체/확장했는지 설명하는 것이 좋다.

| 참고 필수/권장 항목 | 살만해 대응 기능 | 설명 |
| --- | --- | --- |
| 주택 실거래가 정보 수집 | `transaction_history`, `region_price_stat`, `building_price_stat` | 국토교통부 실거래가를 정규화해 DB에 저장하고 지도/시세 분석에 활용 |
| 주택 실거래가 검색 | 지도 탐색, 매물 주변 실거래가 조회, 시세 분석 API | 검색 조건과 선택 매물 기준으로 실거래가/통계 정보를 제공 |
| 회원 관리 | 이메일 인증, 회원가입 | Spring Security + BCrypt + Redis 이메일 인증으로 구현 |
| 로그인 관리 | 로그인, 로그아웃, 토큰 갱신 | JWT access token과 Redis refresh token rotation 적용 |
| CCTV 설치 현황 수집/검색 | `safety_facility`, 안전시설 API, 안전 점수 배치 | CCTV뿐 아니라 비상벨, 보안등, 치안시설까지 확장 |
| 주변 환경 정보 검색 | 안전시설 레이어/안전 분석 | 환경 지도점검 대신 계약 안전성에 가까운 생활안전 데이터를 활용 |
| MSA REST API | Spring Boot와 backend-ai 분리 | 프론트는 Spring만 호출, AI/RAG는 FastAPI 내부 서비스로 분리 |
| OAuth | 이메일/JWT 인증으로 대체 | OAuth는 1.5차 확장 후보로 관리 |
